MissionDebug — how it works

The incident-memory layer for a robot fleet. It captures the 60 seconds around every failure, lets you replay it, and makes the fleet's entire incident history queryable — so teams stop re-solving the same problem.

The three pieces

On each robot

Agent

60-second rolling buffer always holds the last 60s of the topics you care about
Detectors fire stall, path-deviation, low-battery, topic-dropout, or your own YAML rules
Writes a recording + summary a standard MCAP file + a plain-text summary, then reports it to the hub
On a server (you host)

Hub

Incident memory summaries, "has this happened before?", resolutions, MTTR & recurrence
Fleet rollup dashboard KPIs across every robot; operational health
Serves recordings on demand streams the MCAP from the robot (or S3) only when someone scrubs it

The capability layers (bottom → top)

1 · Capture the primitive
Agent keeps a 60s buffer and snapshots an MCAP the moment a detector fires.
2 · Replay how a capture works
Scrub the recording in the browser — timeline, per-topic charts, JSON inspector, annotations, shareable timestamp links.
3 · Incident memory BUYABLEwhat gets bought
Structured summaries, "has this happened before?" similarity, resolution tracking, and the fleet dashboard (MTTR, recurrence, top patterns, ROI).
4 · Integrations LIVEremoves adoption friction
Incidents flow out via OpenTelemetry into your Grafana / Datadog / on-call; external alerts can trigger captures (webhooks, medkit Triggers).
5 · AI agent PLANNEDthe differentiator
Ask the incident history in plain English — "why does bot-03 keep stalling, and what fixed it last time?" Turns a dashboard you read into an expert you ask.

Where your data lives

Recordings (big): stay on the robot by default, or your own opt-in S3 bucket — never auto-uploaded. Retention can tier or delete them over time.
Incident memory (small & queryable): lives in the hub's database and survives after the recording is gone. That separation is the product — the 60-second clip is disposable; the memory of the incident is forever.

Private by default

Works fully offline / air-gapped

  • Capture, replay, charts
  • Summaries & "happened before?" search
  • Fleet dashboard, resolutions, MTTR
  • Self-hostable end to end — no mandatory cloud, no login

Reaches out only if you opt in

  • OpenTelemetry → your own collector, on your network
  • AI agent → an LLM (cloud, or a local model for air-gap)
  • S3 upload of recordings (off by default)
  • Each is gated by config — nothing leaves unless you turn it on

Two ways to run it (same software)

Standalone — one robot

Agent + hub + UI on a single robot. Capture & replay, no central server. The free wedge.

Fleet Edition — many robots

Every robot's agent reports to one central hub that aggregates incident memory across the whole fleet. Per-robot-per-month.

Standards-native: MCAP + Foxglove. Complementary to live-ops tools (you debug the robot after the alert, not instead of operating it live).
